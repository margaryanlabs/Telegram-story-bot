## Инженерные причины

`studio.html` — 2258 строк, 13 screen-секций, 18 последовательно подключаемых CSS. V3 `vetogram-noir.css` переопределяет старые селекторы через root-ID и многочисленные `!important`; это подтверждает конфликт владения стилями, а не необходимость следующего override-файла. В `app.js` общий `switchScreen` переключает весь документ и прокручивает окно наверх. Инструменты привязаны к глобальным ID и загружаются до входа в соответствующую задачу.

Точная воспроизводимая ведомость: `python3 scripts/vetogram-experience-inventory.py`. Результат — `v4/source-inventory.json`. Это read-only анализ, не тест готовности продукта.

Ведомость дала: 13 экранов, 18 CSS (565867 байт исходников, 1446 `!important`), 5 статических modal-поверхностей включая welcome, 19 функций `*Sheet`, 0 повторяющихся HTML ID. `npm run check` выполнен на V4: существующие JS syntax checks прошли. `git diff --check` прошёл. Полный npm test/build в этом этапе без изменений runtime не повторялся; новый script не выполняет приложение и не проверяет UX.

| `viewers` / `intelligence` | История → зрители | источник, ограничения, owner, приватность |
| `analytics` | История → аналитика | только доступные данные, no-data ≠ 0, период при наличии данных |

| `voice` / `voicestudio` | Создать → голос; вход из composer | MediaRecorder lifecycle, analyser, очистка URL и потоков |
| `studio` / `creator` | Создать → стикеры | отдельный старый route-id studio; не путать с alias studio → story-engine |
| `relay` | Личное → инструменты → Relay | текущие probe/bootstrap действия без фоновой активации |

Основная навигация: **Чаты · Истории · Создать · Защита · Личное**. «Создать» открывает компактный chooser (история/голос/стикер), а не ещё один dashboard. ИИ доступен из заголовка и контекста; он не забирает шестую вкладку. Переписка, редактор и fullscreen-viewer — вложенные задачи с Back, без глобального dock поверх инструментов. Старые deep links сохраняет route adapter.

## Модальные поверхности

Ведомость включает статические `telegramThreadPhotoDialog`, `sePreviewDialog`, `vg26CommandDialog`, общий `sheet` и функции `*Sheet` в `app.js`. Дополнительно при миграции проверить динамические story viewer в `telegram-stories.js`, unified onboarding в `privacy.js`, меню/медиа в `telegram-chats.js`, studio preview и Relay overlays. Автоматическая ведомость не доказывает полного охвата динамического DOM.

Новые общие примитивы: `Sheet` с фокусом/возвратом/Back, `ActionMenu`, `ConfirmAction`, `PermissionStep`, `MediaViewer`, `Toast`, `InlineError`, `Skeleton`. Только один верхний modal-owner; закрытие панели не должно отменять внешний send/publish consent незаметно. Камера/микрофон — только по действию пользователя.

## Архитектура постепенной миграции — без нового продукта

1. **Контракты перед переносом.** Зафиксировать существующие routes, события, selectors, API payloads и draft fixtures. Новые screen adapters вызывают существующие контроллеры. Никакой поддельной identity для визуальной QA.
2. **Внутри `public/experience/`:** `shell/`, `navigation/`, `sheets/`, `motion/`, `i18n/`, `screens/{chats,personal,stories,editor,vault,ai,voice,stickers,insights,relay}`. Использовать существующие ES modules; новый framework не нужен ради реорганизации.
3. **Владение DOM.** Извлекать по одной секции в render/mount/unmount-функции; сначала разрешить dependency injection существующих контроллеров, затем уходить от document-global ID. Не иметь одновременно старый и новый подписанный owner-controller для одного экрана.
4. **Владение CSS.** Один token layer и scoped CSS каждого перенесённого модуля; удалить подключение его старых правил только после регрессионной проверки. Не вешать V4 поверх 18 старых stylesheet. Незавершённые модули остаются под adapter, с явной ведомостью долга.
5. **Данные.** Transport адаптеры `/api/*` не меняют контракт. Кэш включает owner и request epoch. Logout/account change снимает listeners, aborts, selection, temporary URLs и AI context. Не менять ключи/формат старых черновиков; versioned read adapter прежде любых расширений.
6. **Локализация.** Расширить существующий locale core стабильными ключами; ru/en/hy словари, plural/date форматирование, каталог ошибок. Переносить статические строки и aria-метки каждого мигрируемого модуля. Пользовательский чат/архив/AI-текст не переводить обходом DOM. Полноту проверять missing-key report, а не fallback.
7. **Motion/gesture.** 120–180ms feedback, 200–280ms навигация, прерываемые transform/opacity, spring только на прямом действии. Reduced motion без spatial moves. Pointer capture после определения намерения; canvas pinch не блокирует page zoom за пределами холста. Системный Back и явные кнопки дублируют жесты; destructive action не висит на одном случайном swipe.
8. **Переход по модулям.** Shell → onboarding/чаты → editor/publish/viewer → vault → AI → voice/stickers → insights/relay/остальные sheets. Маленькие логические коммиты; родительские ветки не переписывать, upstream head перепроверять до push/rebase.

## Граница возможностей

Реально есть в исходниках: Telegram API adapters, archive, AI consent/provider path, renderer JPEG, text layers/drag, owner-scoped drafts/history, локальный Remix, optional MediaRecorder clip, audio processing. Наличие кода не доказывает работу интеграции на текущем deployment.

План V4: direct title selection, pinch, shared transitions, новые меню/галерея и экранная композиция. Пока не реализовано. Различающийся Remix обязан менять layout/типографику/кадрирование и проходить визуальное сравнение. Local Remix всегда явно local. Реальный AI Director использует provider path и согласие; no provider — объяснимая недоступность.

JPEG не содержит музыку/анимацию. Скачиваемый короткий клип браузерозависим, не равен гарантированной Telegram video Story. Напоминания показываются как работающие только после проверки фактического scheduler/backend. Аналитика, viewer и archive не получают придуманные значения.

## Приёмка после выбора

Для каждого из 13 экранов и всех модальных сценариев: главное действие понятно за 3 секунды; шаги измерены; shared interactions; качество и согласованность; loading/empty/error; кнопки и жесты; регрессии контрактов; структурное UX-отличие. Проверить 320/360/390/430/725/768/desktop, portrait/landscape, клавиатуру, focus, safe areas, Back, scroll-restoration и конфликт жестов. 725px — только viewport, не физический Fold.

Обязательные реальные цепочки: открыть чат → поиск сообщения; фото → текст → drag → undo → save → reload draft → review публикации; архив edit/delete; микрофон → запись → прослушивание/сравнение → экспорт; AI prefill → consent → draft → отдельное подтверждение внешнего действия. Два согласившихся аккаунта проверяют owner isolation и отсутствие чужого содержимого.

BEFORE/AFTER после реализации снимаются при одинаковых viewport, данных и состояниях. Сейчас имеется только V3 BEFORE и V4 design concepts; сравнением готовых реализаций это не является. Полная сборка V3 в прошлом отчёте не считается повторно выполненной проверкой V4.

Production, merge, миграции, секреты и платные сервисы в этом этапе не затрагиваются. Масштабная реализация ждёт выбора пользователя.
